# Compact artificial action-plan training views

These are authored synthetic plans, not captured private model reasoning. The
first scaled set has 13 literal code/shorthand templates, instantiated across
10,842 existing CLI training actions in 10,008 tasks. The templates were authored
once and reused deterministically, not generated by 10,842 separate model calls.
The actual author model identifier was not exposed and remains null. Each note
is 12–18 tokens with the pinned SmolLM2 tokenizer. No test packets were read.

Original files remain immutable under `data/artificial-reasoning-cli-v2`. Notes
state intended operations rather than future outputs or final answers. Recovery
notes require the preceding observed missing-file failure. The frozen builder
checks tool/Python-AST shape, action position and visible task prerequisites.
This set broadens compact-plan formatting coverage, not semantic task diversity.

## Separate admission

`picoagent.data.artificial_plans` verifies the observed native base snapshot first.
A pinned independent review must bind the exact annotation corpus, normalized
literal template bodies and immutable tokenizer identity. Per-row validation
binds the original visible-prefix and proposed-action hashes. Template family,
tool, action position and prerequisites must match. No arbitrary `approved=true`
flag opens admission. The training loader additionally requires both
`allow_native_teacher_observed` and `allow_artificial_action_plans`.

The view replaces originally empty assistant tool-call content with a compact
plan and consistently rewrites subsequent model-visible prefixes. It explicitly
labels those contexts **synthetically augmented, not observed**. Tool arguments,
raw observations, execution receipts and final answers stay unchanged. Original
records remain in the self-contained base snapshot. This is not an assertion
that the original teacher saw the inserted plans.

The initial builder selects alternating sorted task IDs within each eligible
training family: one normal or annotated view per base task. It does not inflate
unique-task counts or duplicate every trace. Development examples are unchanged.
Compaction traces are not post-hoc annotated in this version; their actual
summary requests and decisions require their own observed-context provenance.

Before encoding, training checks the actual pinned tokenizer asset/model revision
and re-encodes every unique note. A note over 24 tokens fails, as does an overlong
complete SFT example. There is no silent truncation. More aggressive compression
and a learned-performance comparison remain later experiments.

An artifact marked `training_eligible=false` is still only a candidate. A separate
sealed augmentation snapshot and explicit training configuration are required;
this document does not claim that a pretrained model has been fine-tuned.

## Rebuild the final view

After creating the immutable native collection from the baseline and knowledge/
search supplement, run `HF_HUB_OFFLINE=1 python scripts/build_native_training_view.py`
with the reviewed tokenizer cached. The destination must be new. `--base` and
`--output` support rebuilding into a separate directory for hash comparison.
The script does not execute trace commands, query a teacher or allocate compute.
It strictly verifies native evidence, verifies the pinned review and actual note
token counts, copies every evidence byte with hashes, and validates the result.
